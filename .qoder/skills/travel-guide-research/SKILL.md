# 旅游攻略研究（TravelGuide Assistant 包装）

本技能通过 HTTP API 驱动本地部署的旅游攻略助手。任务耗时较长（快速 3 分钟 / 标准 6 分钟 / 深度 15~25 分钟），必须**后台启动服务 + 轮询任务**，严禁同步等待。

## 前置约定

- 服务默认地址：`http://127.0.0.1:8000`
- 全局只允许一个浏览器采集任务，多任务会自动排队（日志显示"排队中"属正常）
- 项目路径：以用户工作区或用户提供的路径为准（记为 `$PROJ`）

## 工作流程

```
任务清单（复制跟踪）：
- [ ] 1. 确认/启动服务
- [ ] 2. 发起研究任务
- [ ] 3. 轮询至终态
- [ ] 4. 输出报告并做二次加工
```

**1. 确认/启动服务**

先 `GET /api/health`。返回 200 则跳到第 2 步；否则后台启动：

- Windows：在 `$PROJ` 下执行（后台运行）
  `.venv\Scripts\python.exe run_server.py`，`.venv` 不存在则用 `python run_server.py`
- macOS/Linux：`python run_server.py`（后台）

启动后等待 3 秒再重新探测 `/api/health`，最多重试 3 次。

**2. 发起研究任务**

```
POST /api/research
Content-Type: application/json

{"keyword": "西湖", "mode": "standard", "force": false}
```

- `mode`：`fast`（约 3 分钟）/ `standard`（约 6 分钟，默认）/ `deep`（约 15~25 分钟，含口播转写，出发前深度规划用）
- `force: true`：跳过知识库缓存强制重新采集；用户未明确要求时保持 `false`（7 天内重复关键词会命中缓存，约 30 秒出报告）
- 响应：`{"job_id": "..."}`，记录备用

**3. 轮询至终态**

每 20 秒 `GET /api/jobs/{job_id}`（首次可 5 秒后先探一次），直到 `status` 不是 `running`：

| status | 含义 | 处理 |
|---|---|---|
| `running` | 进行中 | 查看 `stage`/`log` 末尾几行，向用户同步关键进度（如"已采集 3/8 条视频"），继续轮询 |
| `done` | 成功 | `result.markdown` 即完整报告；`result.stats` 含统计 |
| `error` | 失败 | 读 `error` 字段，按下方"常见错误"向用户解释，不要重试采集 |
| `cancelled` | 已取消 | 告知用户任务已终止 |

轮询期间如用户要求停止：`POST /api/jobs/{job_id}/cancel`（当前步骤结束后生效），**不要杀服务进程**。

**4. 输出报告与二次加工**

- 报告头部含「速览：可取/不可取」三栏（值得做/别踩坑/有争议），先给用户呈现这部分
- 置信度语义：`多源一致`=可作事实陈述；`单源`=谨慎转述；`存分歧`=并列双方说法
- 用户要求行程规划时：基于报告要点编排，避开"别踩坑"项，对 `⚠️出发前请核实` 的时效信息保留提醒
- 报告文件也在本地 `$PROJ/data/reports/`，需要时可用 `GET /api/reports/download?name=文件名` 下载

## 常见错误与话术

| error 特征 | 原因 | 告知用户 |
|---|---|---|
| 未检测到登录态 | 抖音登录态失效 | 需本人到弹出的浏览器用采集小号扫码（一次性） |
| 疑似选择器失效 | 抖音页面改版 | 查 `$PROJ/data/debug/` 快照，对照 `crawler/douyin.py` 顶部 `SEL_*` 常量修复 |
| API Key 无效/欠费 | LLM 凭据问题 | 在项目目录执行 `python run_cli.py setup` 重新配置 |
| 没有采集到任何内容 | 关键词过冷或改版 | 建议换更通用的关键词（如"武功山"代替"武功山帐篷节攻略"） |

## 禁止事项

- 不要并发发起多个采集任务（会排队拉长总耗时，除非用户明确要求）
- 不要修改频控/限量配置来提速（合规设计，会显著增加账号风控风险）
- 不要把报告中的来源链接替换或省略（溯源是报告的核心价值）
