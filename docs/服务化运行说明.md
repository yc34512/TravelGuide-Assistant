# TravelGuide 服务化运行说明

日期：2026-10-25。适用于本轮 S0—S7 之后的代码。默认仍是本地单用户 SQLite 模式；
服务模式（MySQL/Redis/API Token/独立 Worker）需要额外配置。未启动的依赖不会被自动安装或启动。

## 1. 安装与默认启动

```bash
# 项目根目录
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m pip install -r requirements-service.txt   # 可选：MySQL/Redis 模式
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt       # 可选：跑测试/容量脚本

.venv/Scripts/python.exe run_server.py
```

默认行为：

- `STORAGE_BACKEND=sqlite`，任务库 `data/tasks.db`，报告版本库 `data/reports.db`；
- `WORKER_ENABLED=true`、`WORKER_EMBEDDED=true`：API 进程的 lifespan 启动
  pipeline 容量 1、query 容量 2 的有界 Worker；
- 不再为每个请求创建长任务线程；任务先写入 `task_jobs` 再执行；
- 页面与旧 API 字段兼容：`status` 仍是 `running/done/error/cancelled`，
  新字段 `state` 提供 `queued/running/retry_wait/needs_review/cancelled/succeeded/failed`。

只想跑离线验证（不启动服务）：

```bash
.venv/Scripts/python.exe scripts/verify_all.py
```

## 2. 独立 Worker（推荐的服务模式）

嵌入 Worker 适合本地单进程演示。要跑多 API 进程或把长任务移出 API 生命周期：

```bash
# 终端 A：API，不启动嵌入 Worker
WORKER_EMBEDDED=false .venv/Scripts/python.exe -m uvicorn api_server:app \
  --host 127.0.0.1 --port 8000

# 终端 B：pipeline（采集/规划，容量 1，带单例租约）
.venv/Scripts/python.exe -m service.worker --role pipeline

# 终端 C：query（复杂追问，容量 2）
.venv/Scripts/python.exe -m service.worker --role query
```

或一个进程同时启动两类：`python -m service.worker --role both`。
`--once` 处理到队列暂时为空后退出，适合测试/批处理。

注意：

- pipeline 使用 `worker:pipeline` 单例租约；不要同时启动嵌入 Worker 和外部 pipeline，
  第二个会明确失败/不领取。
- 多个 API 进程必须使用外部 Worker，否则每个 API 进程都会启动嵌入 Worker。
- API 与 Worker 必须能访问同一个报告目录和同一个任务库；本机默认满足。
- 图检查点仍绑定固定 `CHECKPOINT_REALM=local-planning` 的 SQLite 目录；不要通过加
  `WORKER` 数量来宣称跨主机恢复。

## 3. 常用配置

全部通过 `.env` 或环境变量设置（默认值见 `config.py` 与 `.env.example`）：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `STORAGE_BACKEND` | `sqlite` | `sqlite` / `mysql`；mysql 缺 DSN 明确失败 |
| `MYSQL_DSN` | 空 | 如 `mysql+pymysql://user:pass@127.0.0.1:3306/travelguide?charset=utf8mb4` |
| `TASK_DB_PATH` | `data/tasks.db` | 任务/事件/步骤/租约 |
| `REPORT_DB_PATH` | `data/reports.db` | 报告版本与证据 |
| `KNOWLEDGE_DB_PATH` | `data/knowledge.db` | 知识库/向量（测试/演示可改独立目录） |
| `REPORT_DIR` | `data/reports` | 报告文件目录 |
| `AUTH_MODE` | `local_single_user` | 本地演示 / `api_token` |
| `WORKER_ENABLED` | `true` | API 是否启动嵌入 Worker |
| `WORKER_EMBEDDED` | `true` | `false` 时必须单独启动 Worker |
| `WORKER_ROLE` | `both` | `pipeline` / `query` / `both` |
| `PIPELINE_WORKER_CAPACITY` | `1` | 长流程执行容量 |
| `QUERY_WORKER_CAPACITY` | `2` | 复杂追问容量 |
| `MAX_QUEUE_TOTAL` | `200` | 排队上限，超过返回 503 |
| `MAX_ACTIVE_PER_OWNER` | `2` | 每主体未结束任务上限 |
| `WORKER_LEASE_SECONDS` | `90` | 领取租约；过期转 `needs_review` |
| `WORKER_MAX_ATTEMPTS` | `2` | 任务最多执行尝试；重试计数不重置 |
| `CACHE_ENABLED` | `false` | 是否启用 Redis 缓存/限流 |
| `REDIS_URL` | 空 | `redis://127.0.0.1:6379/0` |
| `GLOBAL_MODEL_INFLIGHT` | `2` | 跨进程模型在途槽位 |
| `AGENT_*` | 见 `.env.example` | 工具轮次/调用/路线/聊天/embedding/截止时间 |

配置非法或 mysql 模式缺依赖时会明确报错，不会偷偷改写 SQLite。Redis/embedding/FAISS
属于增强层，缺失时按各自降级链运行。

## 4. 任务 API

提交：

```bash
curl -X POST http://127.0.0.1:8000/api/trip \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: user-42-trip-20261025-1" \
  -d '{"city":"大同","days":2,"hotel":"古城内","preferences":"带老人","excluded_spots":["某点"]}'
```

返回 202：`{"job_id": "...", "state": "queued", "status": "running", "trace_id": "..."}`。
同一 `Idempotency-Key` + 相同请求返回原任务；同键不同请求返回 409；队列/主体容量满返回
503 + `Retry-After`。

查询：

```bash
curl http://127.0.0.1:8000/api/jobs/<job_id>
curl "http://127.0.0.1:8000/api/jobs/<job_id>/events?after=0"
curl -X POST http://127.0.0.1:8000/api/jobs/<job_id>/cancel
curl -X POST http://127.0.0.1:8000/api/jobs/<job_id>/retry
```

`needs_review` 表示外部调用结果不确定或需要人工处理；不会自动重放。`retry` 需要
`attempt < max_attempts`。`quality_status=pass|warning` 独立于任务状态；warning 不会被
`succeeded` 掩盖。

旧接口 `/api/research`、`/api/heat/refresh` 同样改为 202 + `job_id`；旧客户端继续轮询
`GET /api/jobs/{id}` 即可。

## 5. 身份与归属

本地演示（默认）：

```text
AUTH_MODE=local_single_user
```

只算本地演示，不声称多用户隔离。

服务端令牌：

```bash
AUTH_MODE=api_token
python scripts/manage_principal.py create --owner alice
# 输出 token 只显示一次
```

客户端请求带 `Authorization: Bearer <token>`；owner 来自令牌映射，忽略 body 里的
`owner_id`。任务、事件、取消、重试、报告列表/下载、追问、检索均按 owner 过滤。
公共城市攻略可共享；私人报告、版本、证据与 agent trace 不跨用户。

MCP：

```bash
TG_API_TOKEN=<token> python mcp_server.py
```

## 6. 报告版本与变更

新生成的行程报告在文件可读后自动登记为 v1 并激活。接口：

```bash
GET  /api/reports/{report_id}/versions
GET  /api/reports/{report_id}/summary
GET  /api/reports/{report_id}/diff?from_version_id=&to_version_id=
POST /api/reports/{report_id}/changes
POST /api/reports/{report_id}/activate
```

变更请求示例：

```json
{
  "base_version_id": "…",
  "changes": {
    "note": "第二天下雨改室内",
    "excluded_spots": ["乙馆"],
    "preferences": "带老人，少走路"
  }
}
```

变更会创建新的 trip_change 任务、新输入快照与新预算；旧版不改写。新版完成后不会自动激活，
需 `POST /activate` 并带 `expected_active_version_id`；不一致返回 409。
`/diff` 会同时给出旧版/新版在**新约束**下的重检结果（排除点、天数、闭馆日），
差异由代码计算，LLM 只负责解释。

页面：报告页的“行程版本”面板支持查看差异、采用此版、变更此行程；追问区的“深度分析”
走工具 Agent（只读，结果展示证据/停止原因/限制）。深度分析与版本变更只对已登记版本的
行程报告开放；攻略报告仍使用普通追问，返回 409 时请重新生成行程报告。

## 7. MySQL 模式

```bash
pip install -r requirements-service.txt
python scripts/apply_mysql_schema.py \
  --dsn "mysql+pymysql://user:pass@127.0.0.1:3306/travelguide?charset=utf8mb4"
```

配置：

```text
STORAGE_BACKEND=mysql
MYSQL_DSN=mysql+pymysql://user:pass@127.0.0.1:3306/travelguide?charset=utf8mb4
```

迁移：

```bash
# 1) 默认 dry-run，只读盘点，不写目标
python scripts/migrate_sqlite_to_mysql.py

# 2) 明确开发库后导入；源库不删、不 truncate；按主键 INSERT IGNORE，可重入
python scripts/migrate_sqlite_to_mysql.py --execute \
  --dsn "mysql+pymysql://user:pass@127.0.0.1:3306/travelguide?charset=utf8mb4"
```

- 旧知识库数据归入 `local_legacy`；checkpoint 与 browser_profile 不迁移。
- 迁移后对账源/目标行数；少于源行数返回非零，需人工查。
- 业务库迁移与 SQLite 检查点是两个库，没有跨库原子事务；恢复依赖稳定步骤键、
  已保存响应复用与中断核对。
- 本机当前 MySQL 服务未启动，真实合同/并发/切换演练未验收。

## 8. Redis 模式

```text
CACHE_ENABLED=true
REDIS_URL=redis://127.0.0.1:6379/0
```

- 只缓存可重建数据：交通、POI 档案、热度、私人报告检索上下文；
- 键包含 owner/报告版本/模型/切块版本/坐标系/方式/出发时间桶；
- Redis 断开时读路径有界回源，昂贵任务仍受持久队列/额度约束；
- 负缓存只缓存真正的 not_found，不把鉴权/风控/服务异常缓存成空结果；
- 真实 Redis 未启动，集成项未验收。

## 9. 回滚与边界

- 切换到 MySQL 前：可退回 SQLite 快照。
- 切换后已有 MySQL 新写入：不能只改 `STORAGE_BACKEND=sqlite` 就宣称回滚；
  需要反向同步，或让应用继续读 MySQL。本项目未实现双写，也不建议直接双写。
- 报告文件目录必须与 API/Worker 共享；跨主机必须提供受控共享文件或对象存储，
  MySQL 里存一个本机路径不能解决文件可达性。
- 图检查点固定规划执行节点；只验证同节点重启恢复，不宣称任意跨主机接管。
- 真实浏览器点击验收未完成（见验收记录）；页面逻辑用 `scripts/ui_logic_check.js` 验证。

## 10. 演示与排障

不联网演示：

```bash
# 生成合成版本数据（不改正式知识库/报告目录）
python scripts/demo_upgrade.py

# 生成并在 8123 启动
python scripts/demo_upgrade.py --serve --port 8123
```

演示数据在 `data/demo_upgrade/`，城市/点位/价格均为合成夹具。

常见状态：

- `queued`：已持久接收，等待 Worker；检查 Worker 是否启动、pipeline 单例是否被占用。
- `needs_review`：租约过期/外部结果未知/任务失败；查看 `/api/jobs/{id}/events`，
  确认外部请求状态后再 `retry`。
- `503`：队列或主体活跃任务达上限；稍后重试，不要绕过容量。
- `401`：`AUTH_MODE=api_token` 但缺少/错误令牌。
- `STORAGE_BACKEND=mysql` 启动失败：检查 `MYSQL_DSN`、驱动、服务器；不会回退 SQLite。
- Redis 不健康：`/api/health` 的 `cache` 显示不可用；缓存降级但任务/预算仍以数据库为准。
