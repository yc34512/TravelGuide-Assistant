## 1. S0：基线与两处静态风险

### 1.1 采集状态：任务预算与账号会话熔断分离

**反例**（`artifacts/upgrade/s0_counterexamples.json`）：

1. 任务 A 调用 `reset_session("task-a")`，导航计数到 1，并触发验证码熔断；
2. 任务 B 调用 `reset_session("task-b")`：修复前会清零 A 的计数并清除熔断；
3. 修复后 B 返回 `False`，A 的计数与熔断保持；A 收工后 B 才拿到从 0 开始的预算；
4. 熔断只能由人工确认风控解除后调用 `clear_account_risk()`，新任务不会自动解除。

**根因**：`crawler/base.py` 的三个模块全局变量没有区分“当前任务导航预算”与
“浏览器/账号会话风控”；任务入口在拿采集锁之前就重置全局状态。

**修改**：

- `crawler/base.py`：新增 `_active_task`，`reset_session(task_id)` 在另一任务持有时
  不重置并返回 `False`；新增 `end_task()`、`clear_account_risk()`、`session_state()`；
  会话熔断不再被 `reset_session()` 清除。
- `service/research.py`、`service/trip.py`、`service/heatrefresh.py`、`main.py`：
  任务入口传 `job_id`，收口调用 `end_task()`；并发占用时任务明确失败，不共享预算。
- 旧测试中“reset 清除熔断”的断言按新合同更新。

**验证**：`tests_upgrade.TestCrawlerSessionIsolation` 3 项；完整套件包含原风控用例。

### 1.2 FAISS 分数与原始文本对应

**反例**：`index.search` 返回按相似度排序的 `(scores, indices)`；旧代码丢弃
`indices`，把排序后的 `scores` 直接与原记录顺序 `zip`。在原始顺序
`[far, near, mid]`、相似度排序 `[near, mid, far]` 时，`near` 的 1.0 会被贴到 `far`。

**修改**：`core/vector_store.py::_cosine_scores_faiss` 用返回的 `indices` 把分数放回
原始行位置；零向量与维度异常交回纯 Python 降级，保证两条实现判定一致。

**验证**：`tests_upgrade.TestFaissIndexMapping` 用替身 `faiss` 验证原始顺序映射、
正确文本/分数配对、零向量与维度异常；真实 `faiss` 未安装，集成项
`test_real_faiss_integration_if_installed` 明确 skip，不宣称真实包集成通过。

## 2. S1：持久任务与有界 Worker

### 2.1 存储与协议

新增：

- `core/storage/tasks.py`：`task_jobs`、`task_requests`、`task_steps`、`task_events`、
  `principals`、`resource_leases`；状态 `queued/running/retry_wait/needs_review/
  cancel_requested/cancelled/succeeded/failed`；`quality_status` 独立。
- 提交在同一 `BEGIN IMMEDIATE` 事务写请求与任务；`(owner_id,idempotency_key)` 唯一，
  同键同内容返回原任务，同键不同内容抛 `IdempotencyConflict`。
- 容量在写事务内检查：总队列上限、每主体活跃上限；拒绝返回 503/Retry-After。
- 领取使用短事务 + 条件更新，写入 `lease_owner/lease_expires_at/generation`，
  事务提交后才执行外部工作；心跳、进度、终态写入都校验 owner+generation。
- 租约过期转 `needs_review`，不自动重放；人工 `retry` 才回 `retry_wait`，重试计数保留。
- 事件表自增 `event_id`，支持 `after` 游标；trace_id 贯穿任务。
- 步骤账本 `task_steps` 以 `(job_id,step_key)` 唯一，同输入可复用、输入变化拒绝静默复用。

`service/worker.py`：固定容量线程池（pipeline 1、query 2），任务领取、心跳、进度同步、
协作式取消、重试/待复核、单例 pipeline 租约。`JOBS` 只作为旧接口的缓存视图。

### 2.2 API 与执行入口

- `/api/trip`、`/api/research`、`/api/heat/refresh` 改为提交持久任务并返回 202；
  支持 `Idempotency-Key`。
- `/api/jobs/{id}` 读取持久状态；`/api/jobs/{id}/events?after=` 增量事件；
  `/api/jobs/{id}/cancel` 幂等取消；新增 `/api/jobs/{id}/retry`。
- `service/research.start_job`、`service/trip.start_trip`、`service.heatrefresh.start_heat_refresh`
  改为提交持久任务，不再创建每请求长线程。
- 嵌入模式在 FastAPI lifespan 启动 Worker；外部模式用 `python -m service.worker`。
  pipeline 单例租约阻止两个执行节点同时采集。

### 2.3 验证

`tests_service.TaskStoreTest` / `WorkerTest`：幂等、容量、双消费者、过期写回、
取消、事件游标、未知外部状态、重试耗尽、协作取消、步骤幂等、单例；`tests_service` 32 项通过
（含 S2/S3/S5 用例，详见验收记录）。API 冒烟覆盖提交、幂等重放、409、状态、事件。

## 3. S2：MySQL、迁移与身份

### 3.1 适配代码

- `core/storage/mysql_tasks.py`：InnoDB 短事务，`FOR UPDATE SKIP LOCKED` 领取，
  单行 `admission_gate` 串行化容量检查；任务、事件、步骤、主体、资源租约合同与 SQLite 一致。
- `core/storage/mysql_reports.py`：报告、不可变版本、证据表；激活 CAS。
- `STORAGE_BACKEND=mysql` 但缺少 `MYSQL_DSN`/驱动时明确报错，不回退 SQLite。
- `requirements-service.txt` 锁定实测可安装/导入版本：SQLAlchemy 2.1.5、PyMySQL 1.2.3、
  alembic 1.20.0、redis 6.4.0。
- `scripts/apply_mysql_schema.py` 幂等建表；`migrations/README.md` 说明本轮未引入
  Alembic 版本链的原因与后续要求。

### 3.2 身份

- `core/auth.py`：`local_single_user`（本地演示）与 `api_token`（服务端哈希令牌）。
- `owner_id` 来自鉴权；任务、事件、取消、重试、报告列表/下载、追问、检索均按归属过滤。
- `scripts/manage_principal.py` 创建/禁用令牌；MCP 客户端支持 `TG_API_TOKEN`。

### 3.3 迁移

`scripts/migrate_sqlite_to_mysql.py`：

- 默认 dry-run，只读盘点 `knowledge.db`、`tasks.db`、`reports.db`、`planning/runs.db`；
- 记录表、行数、列、主键、向量维度/collection、旧任务与版本数量；
- `--execute --dsn` 才导入开发库；`CREATE TABLE IF NOT EXISTS` + 主键 `INSERT IGNORE`
  可重入，不删源库、不 truncate；
- 知识库旧数据加 `owner_id=local_legacy`；checkpoint 与 browser_profile 不迁移；
- 导入后输出源/目标行数对账，少于源行数返回非零。

本次 dry-run 结果：legacy jobs 43，task_jobs/task_steps/task_events/report_versions
均为 0，`vec_items` 0。真实 MySQL 导入未执行。

**未验收**：本机 MySQL 8.0 已安装但服务未启动，未取得可用账号；真实 MySQL 合同、

## 4. S3：Redis 缓存、限流与容量闸门

- `core/cache.py`：Redis/NoOp、键规范、TTL、single-flight、负缓存、故障降级；
  导入不联网。键包含：
  - route：坐标系、方向、起终坐标、方式、5 分钟出发桶；
  - poi：实体 ID、素材版本、档案策略；
  - heat：城市、来源版本；
  - context：owner、报告版本、embedding 模型、切块版本、问题哈希。
- `core/geo.py`：交通查询走缓存，只有成功方案才写缓存；失败/配额错误不写成“没有路线”。
- `core/rag.py`：追问上下文缓存带 owner/报告版本/模型/切块版本；不按城市共享私人上下文。
- `core/limits.py`：`resource_leases` 持久槽位，用于全局模型在途调用；
  Redis 只做限流加速，不可用时允许但由持久队列/额度兜底。
- API 对 trip/research/heat/agent/change 做 Redis 固定窗口限流；Redis 关闭时 NoOp。

**验证**：`tests_service.CacheAndLimitTest` 覆盖键条件、正/负缓存、Redis 故障、单飞、
跨 store 实例槽位、真实客户端连接失败有界；真实 Redis 服务器未启动，集成未验收。

## 5. S4：复杂追问工具 Agent

新增：

- `pipeline/ask_tools.py`：四个工具 `read_report/search_knowledge/get_evidence/query_route`，
  统一返回 `ok/data/evidence_refs/as_of/source_version/error_code/retryable/truncated`；
  参数、top_k、文本长度、POI ID、owner、工具次数、路线次数、embedding 次数均校验。
- `pipeline/ask_agent.py`：真实 Function Calling 循环——模型产生 tool_calls，
  Python 执行并持久记录 `agent_tool` 事件，结果回填为 tool 消息；最终回答要求 JSON，
  代码核查 evidence_ids 是否存在；预算/超时耗尽后不再偷偷发总结请求。
- `/api/ask` 默认 `mode=report` 保持同步快路径；`mode=agent` 返回 202 + job_id，
  由 query 队列执行；结果包含 answer、evidence_refs、limitations、stop_reason、tool_calls、usage。
- 全局模型槽位（`GLOBAL_MODEL_INFLIGHT`）在 Agent 执行期间持有，容量满时返回明确停止原因。

**验证**：`tests_agent` 10 项通过：真实 tool_calls 回填、证据原文、错误证据编号拒绝、
未知工具、预算耗尽不额外请求、embedding 检索 scope、owner 报告解析、路线工具预算。
`scripts/eval_agent.py` 4 个固定题：4 条工具链完成、4 条证据绑定、4 条答案包含预期、
2 条检索上下文命中预期引文（另 2 题本就是拒答/注入，期望无引文）。

**未验收**：没有调用真实付费模型，不能据此声称真实模型准确率、token 节省或延迟改善。

## 6. S5：行程变更、版本与差异

- `core/storage/reports.py`：`reports/report_versions/report_evidence`；
  版本不可变，保存 parent、请求、素材 manifest、content hash、quality/artifact/index 状态。
- 初次报告在文件可读后自动 active；变更版本必须显式激活。
- `service/report_versions.py`：
  - 变更合并（天数/住宿/偏好/指定点/新增或取消排除/说明），禁止换城市；
  - 变更任务走新输入、新运行、新预算，复用仍有效素材；
  - `diff_versions` 由代码比较点位增删、时段移动、交通、约束、证据、质量；
  - 旧版与新版都在**新约束**下重检（排除点、天数、闭馆日），diff 同时给出两边结果；
  - 激活 CAS：`expected_active_version_id` 不一致返回 409。
- API：`POST /api/reports/{id}/changes`、`GET .../versions`、`GET .../diff`、
  `POST .../activate`、`GET .../summary`；添加 `/api/jobs/{id}/retry`。
- 页面：版本列表、查看差异、采用此版、变更此行程；历史卡片传递 report_id；追问增加
  “深度分析”入口展示证据/停止原因/工具调用。
- `scripts/ui_logic_check.js`：从 `index.html` 抽取版本函数，用模拟 DOM/fetch 执行，
  验证版本行、激活/差异按钮、diff 摘要、重检与质量展示。

**验证**：`tests_service.ChangeAndDiffTest`、`ReportVersionTest`、`VersionApiTest` 通过；
UI 逻辑检查通过。真实浏览器：首屏加载成功；点击历史卡片后渲染进程无响应，
未完成点击级验收（疑与页面既有动效层有关，未定位到本次新增代码）。因此不把
“浏览器点击流程通过”写成已验证。

## 9. 已知限制（必须随成果一起说明）

1. **MySQL/Redis 真实集成未验收**：本机 MySQL 服务未启动，Redis 未安装/未启动；
   只完成适配代码、SQL 编译检查与 SQLite 合同测试。
2. **真实模型效果未验收**：Agent 与规划测试使用替身/脚本模型；未调用付费模型，
   不声称准确率、token 节省或延迟提升。
3. **真实浏览器点击流程未完成**：页面首屏可加载；点击历史卡片后 IAB 渲染进程无响应，
   版本 API 与 UI 逻辑已分别验证，但不把整条点击流程标为通过。
4. **真实 FAISS 未安装**：分数映射用替身回归；真实包集成 skip。
5. **检查点仍为 SQLite**：绑定固定 planning realm；只验证同执行节点重启恢复，
   不宣称任意多主机接管。
6. **嵌入 Worker 与 API 同进程**：默认本地模式；服务模式应设 `WORKER_EMBEDDED=false`
   并单独启动 pipeline/query Worker。多 API 进程时嵌入 Worker 会重复，需外部 Worker。
7. **旧报告未版本化**：升级前生成的报告没有 `report_versions` 记录；需要重新生成才能
   使用版本/变更功能。
8. **证据 ID 冲突策略**：同一版本内若同一原始 evidence_id 对应多个摘录，当前保留第一条；
   不影响原文存在性，但会限制同源多句引用的数量。
9. **队列容量与延迟**：容量测试是本机 SQLite + mock，不是线上 QPS；未测真实采集/模型
   外部延迟下的完整生成容量。
