# 原文证据与引用校验

更新：2026-10-14。替换提取与摘要中的前15字匹配，统一评论、文案和口播证据。没有新增依赖，没有调用真实LLM评测。

## 链路

素材登记内部编号 → 提取claim与evidence_id/excerpt → 代码完整匹配与来源绑定 → 批量支持性复核和多源聚类 → 规划/摘要选择quote_id → 代码回填原话。

- 素材池只包含实际送给提取模型的评论（前50条）、文案与口播；编号包含来源与文本指纹，不含评论者身份。
- 完整摘录必须连续存在于指定原文中，来源必须对应同一视频。只去除摘录首尾空白，不做相似度或前缀放行。
- quote与source从匹配原文和采集对象回填。评论引用不再先截成80字；完整快照、摘录起止位置与指纹随要点保存。
- 文案/口播也需要原文证据。兼容旧响应时仅接受完整评论引用，或能够逐字定位在文案/口播中的结论；空quote不能绕过校验。
- 无有效证据的提取条目直接丢弃，而非清空quote后继续保留claim。

## 支持性与置信度

原文匹配只证明“输入中有这段文字”，不能证明总结正确或素材本身真实。代码先检查明显的数字缺失和老人免票年龄条件遗漏；这些规则不是完整的语义判断器，数字文字表达等特殊情况可能被保守拒绝。

在原有批量交叉验证调用中附完整原文，同时请求支持性结论、分组与冲突；不是每条要点单独调用。状态为supported/rejected/pending/unverified；仅supported且证据快照有效的条目可进入规划和评论引用名单。

完整原文用于排除转述、辟谣、反例和断章取义。支持性缺失、重复编号、非法状态或请求异常都降为待确认，评分0、有效来源数0。拒绝或待确认条目不能增加其他条目的印证数，不能制造冲突；营销号也不计有效来源。

批次保留完整上下文，按原有条数上限及30,000字符上限分批；超过6,000字符的单条上下文、超过600字符的结论保守标待确认，不裁去上下文后声称已验证。分批可能漏掉跨批印证，沿用保守降级；增加原文会增加输入token，字符上限不是精确token预算。

支持性仍由模型判断，存在误判，不能对外承诺“杜绝所有幻觉”。官方事实层、时效核查及多源验证仍有必要；ASR输入文本的字面匹配也不等于音频转写绝对准确。

## 下游与旧数据

- 摘要输出quote_ids，行程输出按景点限定的pitfall_quote_ids；未知编号、其他景点编号与重复编号丢弃。最终quotes/pitfall_quotes保持原字符串列表接口，但字符串由代码回填。
- 摘要正文要求要点编号依据，拦截无依据字段和明显数值/条件变化；复杂摘要语义仍可能被模型曲解，此层不是完整语义证明。
- 未获支持的条目不进入景点档案、选点统计、规划和避坑事实；攻略报告以“待确认的素材结论”单列，不进入事实速览与来源编号。
- 采集缓存保存原始VideoItem，当前本来就会重新提取，新校验同样覆盖缓存命中；没有修改或清理用户的原始缓存。
- 老要点缺证据时标unverified。历史摘要不能仅靠旧quotes字符串恢复“评论原话”；检索与压缩追问均重新从有效证据回填。
- 新行程快照记录evidence_version=1；新报告索引使用版本命名空间，旧索引没有校验版本的记录不再被当作已验证语料召回。历史报告的其他信息标记未完成原文复核，作为待确认线索；不删除已有索引或报告。

## 测试

tests_evidence.py使用固定模型响应验证真实摘录、假后缀、超长引用、数字/年龄变化、错来源、空quote、文案/口播、篡改快照、辟谣上下文、批量支持状态及其降级、多源计数、摘要和行程引用、历史检索与追问出口。

tests_offline.py通过load_tests接入新套件，既有CI命令同时执行证据链回归。原来“真实前缀+编造后缀应保留”的测试已改为必须拒绝；格式与置信度夹具补充合成证据，保留原有引用和来源计数断言。
